# Лабораторна робота 1: Event Loop та Game Loop

## Тема гри
Космічний корабель (2D симуляція польоту з інерцією та загортанням країв екрана).

## Реалізація
* Ігровий цикл з фіксованим кроком (Fixed Timestep) 60 steps/s через акумулятор.
* Рендер з інтерполяцією (alpha) та підтримкою Retina/High-DPI (`devicePixelRatio`).
* Обробка клавіатури через замикання (`createInput`).
* Чиста функція фізики `integrate(ship, input, dt)` без DOM-залежностей.

## Результати експериментів

### 1. Блокуючий цикл у кадрі
* **Дія:** Додано штучну затримку 50 мс (`while (performance.now() - t < 50)`).
* **Результат:** FPS просів до ~18-20, екран зафризився, час кадру зріс до 50+ мс.
* **Пояснення:** Синхронний код блокує Call Stack. Оскільки JS однопотоковий, браузер не може перейти до виконання черги анімації (`requestAnimationFrame`) та перемалювання екрана (Paint).

### 2. setInterval замість requestAnimationFrame
* **Дія:** Оновлення та рендер переведено на `setInterval(tick, 1000 / 60)`.
* **Результат:** З'явилося мікросмикання (джиттер), симуляція втратила плавність.
* **Пояснення:** Колбеки `setInterval` потрапляють у чергу макротасок (Task Queue) і викликаються з похибкою таймера без синхронізації з апаратною розгорткою монітора (VSync).

### 3. Змінний крок часу замість фіксованого
* **Дія:** Замість фіксованого кроку 1/60 у фізику передавався реальний час між кадрами `dt = frameDuration`.
* **Результат:** При будь-яких просадках продуктивності корабель робить різкі ривки і пролітає повз межі арени.
* **Пояснення:** Нестабільні інтервали накопичують похибку чисельного інтегрування, що робить фізику недетермінованою.
